# Motion Design

Use when Tremor needs movement to communicate state or intent.

## Purpose

- Make transitions feel intentional.
- Use motion to explain state changes.
- Keep animations tied to the tactile product language.

## When To Use

- Screen transitions.
- Interactive feedback.
- Motion language for product moments.

## When Not To Use

- Pure implementation plumbing.
- Copy editing.
- Budget or ops work.

## Inputs

- The state change.
- Timing and pacing goals.
- The message the motion should convey.

## Outputs

- A motion plan.
- Timing and easing choices.
- Notes on what motion is doing for the user.

## Verification

- Motion clarifies rather than distracts.
- The timing feels aligned with touch and audio.
- The effect remains subtle enough to keep the game readable.
