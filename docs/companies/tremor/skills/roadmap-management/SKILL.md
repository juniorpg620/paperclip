# Roadmap Management

Use when Tremor needs to sequence work, surface dependencies, or keep the delivery path coherent.

## Purpose

- Turn a broad plan into a staged sequence of deliverable milestones.
- Keep dependencies visible before they become blockers.
- Keep the delivery project and the operations project aligned.

## When To Use

- Planning the next milestone or release slice.
- Reordering work based on dependencies or risk.
- Turning strategy into issue and project structure.

## When Not To Use

- Writing the strategy itself.
- Running the weekly ops cadence.
- Solving implementation details inside a single issue.

## Inputs

- Current goals and project scope.
- Known blockers, owners, and deadlines.
- Quality and release constraints.

## Outputs

- Sequenced milestones.
- Visible dependency ownership.
- Updated project or issue structure.

## Verification

- Every milestone has an owner.
- Dependencies are explicit.
- The roadmap matches the live work graph.
