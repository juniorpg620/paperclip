# Delegation

Use when broad work needs to become owned, bounded, and trackable.

## Purpose

- Break work into bounded tasks.
- Match tasks to the right owner.
- Make handoffs explicit enough to survive context switching.

## When To Use

- Turning a goal into issues.
- Assigning work across roles.
- Preparing a request for an agent or human.

## When Not To Use

- Solving the work directly.
- Choosing strategy.
- Writing long-form status without a next owner.

## Inputs

- The goal or request.
- Available owners.
- The deadline or priority.

## Outputs

- A decomposed task list.
- A named owner for each task.
- A handoff note with acceptance criteria.

## Verification

- The recipient can act without guessing.
- Ownership is unambiguous.
- Dependencies are visible.
